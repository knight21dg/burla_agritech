## 1. Strategy

Burla is an unknown brand. Nobody is searching for "Burla" yet. Organic growth therefore comes from **product and category intent**, not brand intent:

| Intent type | Example query | Landing page |
|---|---|---|
| Category | "dehydrated mango powder buy online" | `/shop/dehydrated-powders-flakes` |
| Product | "sun dried vadiyalu online" | `/products/[slug]` |
| Regional | "andhra vadiyalu online" | Category + product |
| B2B | "dehydrated fruit powder supplier india" | `/wholesale` |
| Ingredient | "little millet online india" | Product |
| Brand (later) | "burla agri products" | `/` |

**Consequence:** category pages carry real editorial content, not just a grid. A category page with a heading and twelve cards ranks for nothing.

**The strongest long-term lever is a `/journal` section** (recipes, how these foods are made, how to use them). It is deliberately deferred from V1 (`OOS-06`) but the route is reserved. Flagging it now because it is the difference between a site that plateaus and one that compounds.

## 2. URL architecture

Covered in `SITEMAP.md` §5. The SEO-relevant rules:

- Lowercase, hyphenated, descriptive, no IDs, no extensions, no trailing slash.
- Products flat at `/products/[slug]` — one canonical URL per product regardless of category membership (ADR-003).
- Slug changes always write a 301. **A 404 on a previously indexed URL is treated as a defect.**
- No parameter-driven duplicate content: filter and sort URLs are `noindex, follow`.

## 3. Metadata

Generated per route with Next.js `generateMetadata`, sourced from the SEO fields on each product, category and page record, with automatic derivation when staff leave them blank.

| Page | Title pattern | Description source |
|---|---|---|
| Home | `Burla Global Agri Products — [positioning line]` | Site settings |
| Shop | `Shop All Products — Burla` | Static |
| Category | `[Category] — Burla Global Agri Products` | Category description, truncated to 155 chars |
| Product | `[Product] [pack size] — Burla` | Short descriptor |
| About | `About Burla — Our Story` | Page SEO field |
| Quality | `Quality Control & Standards — Burla` | Page SEO field |
| Locations | `Our Locations — Burla` | Page SEO field |
| Wholesale | `Bulk & Wholesale Enquiries — Burla` | Page SEO field |
| Contact | `Contact Burla` | Page SEO field |
| Policies | `[Policy] — Burla` | Static |

**Rules:** titles ≤ 60 characters, descriptions 140–158, both unique across the site (verified by an automated check in CI), and never keyword-stuffed. Descriptions are written to earn a click, not to repeat the title.

### Open Graph and Twitter

Every page emits `og:title`, `og:description`, `og:image` (1200×630), `og:url`, `og:type`, `og:site_name`, `og:locale` (`en_IN`), plus `twitter:card=summary_large_image`. Product pages use the primary product image; category pages use the category hero; everything else falls back to a branded default. Product OG images are generated dynamically with `next/og` when no bespoke share image is set.

## 4. Structured data

JSON-LD, injected server-side, generated by typed builders in `lib/seo/`. **Structured data must describe what is genuinely on the page** — misrepresentation risks manual action, and for a food business it risks worse.

| Schema | Where | Conditions |
|---|---|---|
| `Organization` | Root layout | Name, logo, URL, contact point, social profiles. Address only when verified (`OQ-021`) |
| `WebSite` + `SearchAction` | Root layout | Enables sitelinks search box |
| `BreadcrumbList` | Shop, category, product, content pages | Mirrors the visible breadcrumb exactly |
| `ItemList` | Category pages | Products in display order |
| `Product` | Product pages | **Only when the product genuinely has a price and availability.** In enquiry-only mode, `Product` is emitted without `offers` |
| `Offer` | Inside `Product` | Only with a real price, currency, availability and a stated price validity |
| `LocalBusiness` | Locations | **Only for verified addresses** — never an invented pin |
| `FAQPage` | Where a genuine visible FAQ exists | Never for marketing copy dressed as questions |
| `AggregateRating` / `Review` | **Never in V1** | No reviews exist. Fabricating them is both a policy violation and a consumer-law problem |

**Explicit prohibition:** no `AggregateRating`, no `Review`, no `award`, no `certification` in structured data until the client supplies documentary evidence (`OQ-019`).

## 5. Crawl control

### robots.txt

```
User-agent: *
Allow: /
Disallow: /api/
Disallow: /admin
Disallow: /account
Disallow: /auth
Disallow: /cart
Disallow: /checkout
Disallow: /search
Disallow: /*?sort=
Disallow: /*?filter=

Sitemap: https://[domain]/sitemap.xml
```

Generated by `app/robots.ts` so the domain comes from configuration rather than being hard-coded. Preview and staging deployments emit `Disallow: /` — **a staging site indexed by Google is a real and common failure**, and this prevents it.

### sitemap.xml

Generated by `app/sitemap.ts` from live database content: home, `/shop`, every published category, every active product, all marketing and policy pages. Each entry carries `lastModified` from the record's `updated_at`, plus a considered `changeFrequency` and `priority`. Nothing `noindex` appears in the sitemap. If the catalogue exceeds 5,000 URLs the sitemap splits into an index — architected for, not needed at launch.

## 6. On-page requirements

| Element | Rule |
|---|---|
| `h1` | Exactly one per page, describing the page, matching search intent |
| Heading order | No skipped levels; headings describe structure, never used for visual sizing |
| Internal linking | Every product links to its category; every category links to related categories; the footer carries all ten category links on every page |
| Anchor text | Descriptive. Never "click here", never "read more" alone |
| Images | Meaningful `alt`, descriptive filenames, explicit width/height, `next/image` |
| Canonical | Self-referencing on every indexable page; parameterised URLs point to the clean version |
| `lang` | `<html lang="en-IN">` |
| Content depth | Minimums per page type enforced (`SITEMAP.md` §6) |
| Rendering | All indexable content server-rendered. Nothing important behind a client-side fetch |

## 7. Technical SEO and Core Web Vitals

Search performance is a ranking input and a conversion input. Targets are in `REQUIREMENTS.md` §3.1.

| Lever | Implementation |
|---|---|
| LCP | Hero image `priority` with correct `sizes`; fonts self-hosted and preloaded; server components so no client waterfall |
| CLS | Explicit dimensions on every image; fonts metric-matched via `next/font`; skeletons sized to final content; **no layout-shifting banners or cookie bars that push content** |
| INP | Minimal client JS; heavy work off the main thread; no synchronous third-party scripts |
| TTFB | ISR — most pages served from cache, not rendered per request |
| Mobile | Mobile-first design, real touch targets, no interstitials that Google penalises |

## 8. International readiness

Not built in V1, but not blocked either:

- `og:locale` set to `en_IN` from configuration, not hard-coded.
- URL structure reserves `/[locale]/` — adding it later is a routing change, not a restructure.
- `hreflang` builder exists but emits nothing while there is one locale.
- Currency is a field on every price, not an assumption.
- Country field on wholesale enquiries already captures international demand signal — **use that data to decide whether localisation is worth building.**

## 9. Launch checklist

- [ ] Domain live over HTTPS, `www` → apex (or the reverse) fixed permanently
- [ ] Staging and preview environments returning `Disallow: /`
- [ ] Google Search Console verified, sitemap submitted
- [ ] Bing Webmaster Tools verified
- [ ] Google Business Profile created for verified locations (`OQ-021`)
- [ ] Analytics live and validated (`ANALYTICS.md`)
- [ ] All titles and descriptions unique — automated check passing
- [ ] Structured data validated in the Rich Results Test, zero errors
- [ ] Redirects in place from any prior site (`OQ-034`)
- [ ] No `noindex` left on a production page — checked by crawl, not by memory
- [ ] `robots.txt` and `sitemap.xml` reachable and correct
- [ ] 404 page returns HTTP 404, not 200 — a common and damaging bug
- [ ] Core Web Vitals passing in the field after 28 days of data
- [ ] Crawl of the production site: zero broken internal links, zero orphan pages
